Implementation Notes — English Learning Engine v1

SPEC'in nasıl yorumlandığı, hangi noktalarda saptığım, hangi alternatifleri elediğim ve hangi konuların kullanıcı onayına açık olduğu. Faz 1'in baş ucundaki not defteri.

📅 Faz 1 · 2026-05-18 📦 3 motor · 1 SRS · 56 konu seed 🔌 Köprü: 00_INBOX/*.json 👤 Hedef: B2 (mevcut tahmin B1)

1. Design Decisions (belirsiz noktalar nasıl yorumlandı)

1.1 Köprü mekanizması: JSON + INBOX

Spec "dosya indir → vault INBOX" öneriyordu. Bunu tek köprü prensibi olarak donduruldum: hiçbir motor doğrudan wiki .md dosyalarına yazmıyor, hepsi JSON üretiyor, Claude Code .md köprüsünü kuruyor. Avantajı:

  • HTML çalışırken Obsidian açık olmak zorunda değil.
  • JSON dump'ları 00_INBOX/_archive/YYYY-MM/'da kanıt olarak kalır.
  • Aynı kaynaktan hem human-readable .md hem ileride grafik üretilebilir.

1.2 Veri yükleme: script src + window.ELV1_*

file:// protokolünde fetch() CORS nedeniyle güvenilmez. topics.json ve profile.json dosyalarını tek kaynak olarak tutmak yerine, her birinin yanına topics.js ve profile.js wrapper'larını koydum (aynı JSON literal, window.ELV1_TOPICS = {…} sarmalında). HTML'ler <script src> ile yüklüyor — file:// üzerinden garantili çalışır. Bedeli: iki dosya senkron tutulmalı. Çözüm: tek kanonik olarak .js sürümünü işaretliyorum; .json sadece Claude Code'un kolay parse etmesi için duruyor.

1.3 Rotation algoritması

Spec "6-8 konu, ay-sonu kapsam garantisi, zayıf-konu önceliği, kategori dengesi" istiyordu. Algoritmayı şöyle çözdüm:

  1. weak-topics zorunlu: weak_topics localStorage anahtarındaki konular ilk önce alınır.
  2. Borç skoru: (gün_farkı × (100 - güç)) / 100. Skor en yüksek olanlar üstte. Hiç çalışılmamış konu güçsüz (100) sayılır → erken çıkar.
  3. Kategori sınırı: aynı kategoriden maks 2 (örn. 2'den fazla tense yok).
  4. Hedef: 7 konu (6-8 aralığının ortası). Reroll butonu yeni karışım üretir.
  5. Aynı-gün cache: Motor A ve B aynı set'i görür — çapraz teyit.

1.4 Quiz üretimi (template-based, jeneratif değil)

Spec gerçek dünya örnekleri istedi; ama her gün dinamik üretim için tam jeneratif LLM motoruna ihtiyaç var ve onu burada barındırmayız. Bunun yerine her konunun examples ve common_errors alanlarından üç tip soru türetiyorum:

  • MCQ — doğru örnek + iki manipule edilmiş distractor
  • Fill-in — örneğin ortasından bir kelime gizle
  • ErrSpot — yaygın hata tanımı + öz-değerlendirme (knew/didn't)
⚠️ Bu Faz 1 yaklaşımıdır. Faz 2'de Claude Code'a günlük 6-8 konu için zenginleştirilmiş quiz seti üretmesini öneriyorum — JSON olarak _engine/daily-questions-YYYY-MM-DD.json dosyasına yazsın, motor onu prefer etsin, yoksa template fallback.

1.5 SRS algoritması (SM-2 sadeleştirilmiş)

Anki'nin tam SM-2 implementasyonu daha karmaşık (learning steps, relearning queue). Burada 4-buton modeli (again/hard/good/easy) + interval büyütme yeterli oldu. Bedeli: lapsed cards için ayrı relearning queue yok; "again" sadece interval'i 1 güne sıfırlar. Faz 2'de gerekirse 10dk/1g iki adımlı learning eklenebilir.

1.6 Word Bank → SRS köprüsü

Save'lenen item önce localStorage'da bank'a gider, status: new. vocab-srs.html açıldığında srs alanı boş olanlar otomatik kuyruğa alınır. İlk review srsInit() ile başlatılır. Bu sayede "kaydet" ile "çalış" aşamaları gevşek bağlı kalıyor — kullanıcı istediğinde SRS'i açıyor.

1.7 Tema ve font

4 tema (default dark, light, forest, sunset) ve 4 font boyutu (s/m/l/xl) cycle eden butonlarla. Header'da iki tıkla erişim. Tema seçimi şu an persisted değil — her oturumda dark başlar. Faz 2 nice-to-have.

2. Deviations (Spec'ten kasıtlı sapmalar)

2.1 Tek kaynak yerine iki dosya (.js + .json)

Sapma: _engine/topics.json hem JSON hem JS wrapper olarak duruyor (drift riski).
Sebep: file:// fetch güvenilir değil; Claude Code'un JSON parse'ı en güvenli. İki dosyayı tek source-of-truth olarak işaretledim ve bash script'le kolayca regenerate edilebilir hale getirdim:
cd Artifacts/_engine && { echo "window.ELV1_TOPICS = "; cat topics.json; echo ";"; } > topics.js

2.2 "Aynı 6-8 konu iki motor için" — cache anahtarı

Sapma: Spec teorik olarak "aynı set" istiyor. Ben günlük cache anahtarı (daily_topics_YYYY-MM-DD) kullandım. Yani Motor A'yı 23:55'te açıp Motor B'yi 00:01'de açarsan farklı setler görürsün (tarih değişti).
Sebep: Tarih sınırını zorlamak kullanıcı dostu değil. Edge case → user explicit reroll yapabilir.

2.3 Kapanış metni (Motor A) jeneratif değil

Sapma: Spec'e göre kapanış metni "konuların hepsini ören" olmalı. Şu an her konunun ikinci/birinci örnek cümlesini yan yana diziyorum — gerçek bir akıcı metin değil.
Sebep: Tam jeneratif metin → LLM çağrısı gerekir, bu da kefir prensibini bozar. Faz 2 önerisi: Claude Code, sabah günün set'i hazır olunca _engine/daily-passage-YYYY-MM-DD.json dosyasını üretsin (gerçek paragraf); motorlar fallback olarak şu anki örneklemeyi kullansın.

2.4 TTS sadece Motor B'de

Sapma: Motor A'nın kapanış metninde TTS yok (Web Speech API entegre edilmedi).
Sebep: A'nın ana ürünü modal/quiz akışı; TTS deneyimi B'ye daha doğal oturdu. Faz 2'de A'ya eklenebilir.

4. Edge Cases (düşünülmüş, kodda hesaba katılmış)

4.1 Aynı gün aynı motoru iki kez açma

Sonuçlar üzerine eklenir — ikinci oturum bir "rehearsal" olarak işaretlenir. Güç skoru, son 3 puanın ağırlıklı ortalamasını alır (en yenisi ×3). Yani aynı günde tekrar çalışma overweight olmaz ama borç skoru sıfırlanır.

4.2 Konuda hiç tıklama yapmadan export

Text-first export'unda perTopicResults[t.slug] boş olan konular zero-score olarak gönderiliyor (correct:0, total:0, completed:false). Grammar-first'te ise yalnız tamamlanan konular payload'a giriyor — niyet farkı: A modal-merkezli ("bilerek girdiğin konu"), B tab-merkezli ("metni okudun, gramer otomatik etkide").

4.3 Word Bank dolduğunda

localStorage 5MB sınırı ~5000-10000 kart. Mature kartlar status'ü gereği seyrek görünür, otomatik temizlik yok. Açık soru: 3000+ karta yaklaşınca otomatik export + temizlik önerisi gösterilsin mi?

4.4 Leech kartlar

8+ defa "again" gelen kart status: leech'e geçer. Burada manuel müdahale gerekiyor: ya askıya alırsın (suspend butonu), ya da Claude Code'a "bu chunk'ı içeren bir mini-metin yazdır" diyebilirsin. Otomatik metin oluşturma şu an yok — Faz 2 önerisi.

4.5 Tarih sıfırlama / saat farkı

todayISO() kullanıcının yerel saat dilimine göre çalışır. Seyahatte 12+ saat öne giderse "iki gün üst üste set yenilenir". Bu kasıtlı (lokal akış için doğal). Faz 2'de UTC takip eklenirse açılabilir.

4.6 Boş seed / ilk açılış

Hiç oturum yokken her konunun borcu = 30 (varsayılan), strength = null. Algoritma kategori sınırını koruyup ilk 7'yi seçer. İlk gün set'i random gibi görünür ama ay içinde tüm konuları kaplar.

4.7 JSON dump aynı dakika içinde 2 indirme

Dosya adı YYYY-MM-DD-HHmm dakika çözünürlükte. Hızlı arka arkaya iki indirmede dosya adı çakışır (browser otomatik (1) ekler). INBOX'ta isim çakışması Claude Code'u şaşırtmasın diye: process aşamasında session_id'ye bak, dosya adına değil.

4.8 LocalStorage temizlenirse

Tüm ilerleme silinir. Ama: Vault'a indirilen JSON'lar _archive/'da kalıyor. Geri yükleme aracı henüz yok — Faz 2 nice-to-have. Şimdilik: kullanıcıya export'u haftalık olarak yapması önerilir.

5. Open Questions (kullanıcı onayına açık)

Q1. Günlük konu sayısı sabit 7 mi olsun, yoksa 6-8 arasında rastgele mi? Şu an sabit 7.
Q2. Motor A ve B'yi aynı gün çalışmak zorunluluk mu? Şu an opsiyonel — A çalışıp B atlanırsa o gün çapraz teyit kayıt da yarım.
Q3. Pazar günlerinde sadece weak-topics üzerinden özel "Boss Battle Day" modu açılsın mı? Faz 1'de bunu eklemedim; haftalık review derken Claude Code o gün için weak listesini büyütüyor — yeterli.
Q4. Faz 2'de Claude Code'un her sabah _engine/daily-passage-YYYY-MM-DD.json üretmesini istiyor musun? Bu seni LLM-jeneratif metne taşır ama kefir prensibinden bir tık uzaklaştırır.
Q5. "Yazarlık / felsefe bölüm-sonu metinleri" akışı bu motorla mı yoksa compressed-galaxy/ serisi gibi ayrı bir akışla mı yürüsün? Faz 1'de iki sistem paralel; entegrasyon Faz 3 sorusu.
Q6. SRS'in again_count >= 8 → leech eşiği yüksek mi? Anki default 8. 5'e indirilsin mi?

6. Günlük Kullanım Akışı (özet)

  1. Sabah grammar-first-daily.html'i aç. 6-8 konu kartına dokun, modallarda mini quizleri çöz, beğendiğin chunk'ları "💾 Save" et.
  2. Aynı gün içinde text-first-daily.html'i aç. Aynı konular metnin içinde renkli geliyor. Tab'ları dolaş: Read → Grammar → Vocab → Quiz → Reflect.
  3. Akşam vocab-srs.html'i aç. Vakti gelmiş kartları çalış (again/hard/good/easy).
  4. Üçünde de "📥 Vault'a İndir" → indirilen JSON'ları 00_INBOX/'a sürükle.
  5. Claude Code'a "INBOX'u işle" dediğinde tracking .md'leri güncellenir, log.md'ye giriş düşülür, JSON'lar _archive/'a taşınır.
  6. Pazar: Claude Code haftalık review'u derler → weekly-review.md + yeni weak-topics.md.
